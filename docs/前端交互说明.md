## 2. 核心业务流程

### 2.1 认证流程

```
┌──────────────┐    setAuthMode('login')    ┌──────────────┐
│   PortalPage  │ ──────────────────────────→│   LoginPage   │
│  (未登录首页) │                            │   (全屏覆盖)   │
└──────┬───────┘                            └──────┬───────┘
       │                                           │
       │ 点击"后台登录" 或 头像图标                   │ 选择 tab (用户/管理员)
       │                                           │ 填写表单 → onClick → onLogin(role)
       │                                           │
       │                                    ┌──────▼───────┐
       │                                    │  setUser()    │
       │                                    │  localStorage │
       │                                    │  setAuthMode(null)
       │                                    └──────┬───────┘
       │                                           │
       │  user !== null                             │ user.role === 'admin'
       │  → Navigate /dashboard                     │ → AdminDashboard
       │                                            │ → UserDashboard
       │                                    ┌───────┴───────┐
       │                                    │  Layout 导航栏  │
       │                                    │  随角色切换      │
       └────────────────────────────────────│  admin: NAV_ITEMS
                                            │  contributor: CONTRIBUTOR_NAV_ITEMS
                                            │  guest: 精简导航 + "后台登录"
                                            └───────────────┘
```

**关键状态**：
- `user` (App.tsx) — 登录后从 `null` 变为 `{ name, role }`，持久化在 localStorage `"user"` key
- `authMode` — `'login'` | `'register'` | `null`，控制全屏登录/注册页显示
- Layout 通过 `useOutletContext` 向下传递 `{ user, onLoginRequest, setIsCaseModalOpen }`

**后端对接**：
- 登录 → `POST /api/v1/auth/login` → 返回 `{ token, user }`
- 注册 → `POST /api/v1/auth/register` → 提交申请
- 刷新页面时从 localStorage 恢复 user，同时校验 token 有效性（`GET /api/v1/users/me`）

### 2.2 门户首页（PortalPage）数据加载

```
PortalPage 挂载
  │
  ├─→ GET /api/v1/portal/announcements?page=1&pageSize=3
  │    → 渲染公告通知列表
  │
  ├─→ GET /api/v1/portal/regional-updates?limit=3
  │    → 渲染地方动态（津/渝/川）
  │
  └─→ GET /api/v1/portal/latest-releases?page=1&pageSize=5
       → 渲染最新档案发布（大图新闻 + 小型新闻列表）
       → 底部存储密度 / 申请队列卡片

搜索框交互:
  输入关键词 → GET /api/v1/search?q=xxx&scope=all&page=1&pageSize=20
  热门搜索词 → GET /api/v1/portal/hot-keywords (可缓存)
```

### 2.3 专题库浏览流程

```
SpecialLibrary 挂载
  │
  ├─→ GET /api/v1/library/topics?category=全部领域&sort=latest&page=1
  │    → 渲染卡片网格
  │
  │  用户切换 Tab (宏观经济 / 社会治理 / …)
  │    → 重新请求同接口，传 category 参数
  │
  │  用户点击某专题卡片
  │    → navigate(`/library/${topicId}`)
  │
  └─→ TopicDetail 挂载
       │
       ├─→ GET /api/v1/library/topics/:topicId
       │    → 渲染 Banner + 统计数据
       │
       ├─→ GET /api/v1/library/topics/:topicId/documents?sort=hot&page=1
       │    → 渲染文献列表 + 分页
       │
       ├─→ GET /api/v1/library/topics/:topicId/stats
       │    → 渲染文献类型占比（Policy/Academic/Stats/Case）
       │
       ├─→ GET /api/v1/library/topics/:topicId/experts
       │    → 渲染本专题专家库
       │
       └─→ 点击文献 → navigate(`/library/${topicId}/${docId}`)

DocumentReader 挂载（全屏模态）
  │
  ├─→ GET /api/v1/library/documents/:docId
  │    → 渲染文档元信息 + 文件 URL
  │
  ├─→ GET /api/v1/library/documents/:docId/comments
  │    → 渲染评论列表
  │
  ├─→ POST /api/v1/library/documents/:docId/comments (需登录)
  │    → 发表评论
  │
  └─→ 申请访问权限 → POST /api/v1/documents/:docId/access-request
```

**角色差异**：
- 访客：文献数据脱敏（不显示文件数量）、"登录查看存量"遮盖、Premium 报告遮盖
- contributor：完整浏览 + 评论 + 下载
- admin：同上

### 2.4 案例管理 CRUD 流程

```
CaseManagement 挂载
  │
  ├─→ GET /api/v1/cases?status=all&search=&page=1
  │    → 渲染案例表格
  │
  │  状态筛选 (开放 / 进行中 / 已完成)
  │    → 重新请求，传 status 参数
  │
  │  搜索框输入
  │    → 带 search 参数重新请求
  │
  │  新建案例（仅已登录用户）
  │    → Layout 导航栏 "新建案卷" 按钮
  │    → 打开 CaseManagementModal (覆盖层)
  │
  └─→ CaseManagementModal
       │
       ├─ CRUD:
       │   CREATE → POST /api/v1/cases
       │   READ   → GET /api/v1/cases/:caseId
       │   UPDATE → PUT /api/v1/cases/:caseId
       │   DELETE → DELETE /api/v1/cases/:caseId
       │
       ├─ 文件上传:
       │   FileUploadZone (拖拽/点击)
       │   → POST /api/v1/cases/:caseId/files (multipart)
       │   → 显示上传进度条
       │
       └─ 导出数据:
           导出按钮 → GET /api/v1/cases/export?format=csv
```

## 5. Context / 跨组件通信

```
App.tsx
  │ user state
  │ handleLogin / handleLogout
  │ authMode state
  │
  └─→ Layout (props: user, onLogout, onLoginRequest)
        │
        └─→ Outlet context: { user, onLoginRequest, setIsCaseModalOpen }
              │
              ├─→ PortalPage (已不需要 onLoginRequest prop)
              ├─→ Dashboard
              │     └─→ AdminDashboard / UserDashboard (通过 useOutletContext)
              ├─→ CaseManagement (通过 useOutletContext 获取 user)
              ├─→ SpecialLibrary (通过 useOutletContext 获取 user)
              ├─→ TopicDetail (通过 useOutletContext 获取 user + onLoginRequest)
              ├─→ DocumentReader (通过 useOutletContext 获取 user + onLoginRequest)
              ├─→ ArchiveTaxonomy (通过 useOutletContext)
              ├─→ PersonalizedServices (通过 useOutletContext)
              ├─→ NationalData (通过 useOutletContext)
              ├─→ ResearchReports (通过 useOutletContext)
              └─→ ExpertLibrary (通过 useOutletContext)
```

**通信方式**：纯 React Context 无状态管理库，props 向下流 + `useOutletContext` 读取共享数据。

## 8. 前端需要新增的改动（后端完成后）

1. **API 层封装**：创建 `src/api/` 目录，按模块拆分（`auth.ts`, `cases.ts`, `topics.ts` …），统一处理 token 注入、错误处理、请求/响应拦截
2. **HTTP Client**：建议使用 `fetch` 封装或引入 `axios`，配置 base URL + interceptor
3. **Loading/Error 状态**：Abstract 每个组件加 `isLoading`/`error` 状态，显示骨架屏或错误提示（当前 Demo 无 loading/error 处理）
4. **Token 管理**：存储在 localStorage 或 httpOnly cookie，每次请求自动注入 Authorization header
5. **路由守卫增强**：将 `user` 获取改为异步（先调 `/api/v1/users/me`），首次加载显示全局 loading
6. **真实文件上传**：当前 `FileUploadZone` 仅模拟进度，需对接真实 multipart 上传 + 进度回调
7. **分页组件**：TopicDetail 有静态分页 UI，其他列表页需补充分页
8. **搜索防抖**：全局搜索框加 300ms debounce
